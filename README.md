# 어비스 오토

Windows 10/11 x64용 C# .NET 8 WinForms 프로그램입니다. 화면 캡처 + OpenCvSharp + Windows 한국어 OCR로 판정하고, 실행 엔진에서만 Interception 입력을 보냅니다.

**현재 상태: Windows 배포본에 제공된 원본에서 추출한 사진 6개를 포함했습니다. OpenCV 54개 화면 비교를 통과했습니다. 기존 7개 저장 화면의 Windows OCR은 사용자 PC에서 84개 판정이 모두 일치했습니다. 새 실제 전투 캡처 2개를 포함한 108개 재검사와 실제 반복 완료는 아직 확인이 필요합니다.** 실게임 검증 없이 장시간 반복을 사용하지 마세요.

## 지원 범위

- 제목 표시줄 포함 **1297×873**, 주 모니터 안에 놓인 활성 게임 창만 조작합니다. DWM 가시 경계(보이지 않는 리사이즈 여백 제외)를 캡처와 입력에 동일하게 사용합니다. 창 이동은 반영하지만 크기는 자동 변환하지 않습니다. 현재 화면과 UI 배율이 달라지면 영역을 재검증해야 합니다.
- 허상의 정박지: 메뉴 → 어비스 → 배너 → 입장 SPACE → 전투 대기 → 결과 터치 → 다시 하기 → 전투 대기.
- 난이도·함께하기·우연한 만남 설정은 변경하지 않습니다.
- 메뉴는 서로 다른 정확한 항목 3개 이상, 메인은 채팅의 ‘말하기’로 판정합니다. ESC는 한 번만 입력합니다.
- 목적지는 사진 필수. 입장은 OCR/사진/초록·파랑 배점, 결과는 ‘터치해’ 또는 사진, 다시 하기는 OCR+초록 배경 필수입니다. OCR은 원본 후 실패 시 2배 확대합니다. 다시 하기는 Space 표시를 제외한 글자 영역에서 읽고, 실패하면 흰 글자를 분리한 흑백 2배 OCR을 추가 시도합니다.
- 사진은 TM_CCOEFF_NORMED, 기본 .75, 대상마다 변경 가능. 여러 사진의 최고 점수만 사용합니다. OCR/사진 위치가 겹치지 않으면 합산하지 않습니다. 전체 템플릿이 탐색 영역 안에 들어가야 합니다.
- 입력 전달 실패·커서 불일치·비활성 창·구매/재료 부족 가능 문구·알 수 없는 전투 화면 지속·시간 초과는 오류 정지합니다. 초기 입력 외 최대 3회 재시도합니다.
- 모든 입력 뒤 다음 화면의 명확한 근거를 두 프레임 연속 요구합니다. 전투로 넘어갈 때는 이전 버튼 소멸도 함께 요구합니다. 단순 로딩/버튼 미검출은 성공이 아닙니다.
- F10 및 정지 버튼, 시작 전 3초 알림, 완료 횟수·평균·경과 시간, 정상/오류 알림, 제한 크기 JSONL 로그·오류 사진.
- 전투 판정은 우측 퀘스트 영역의 정확한 ‘허상의 정박지’와 ‘부활 6회’를 함께 요구합니다. ‘클리어’ 끝 글자가 잘려도 이 두 근거가 맞으면 전투를 유지합니다. 채팅·효과·몹 이름만으로 전투라 판단하지 않습니다.
- **부활·음식·재접속·기타 팝업 자동 처리는 미구현/비활성**: 실제 화면이 필요합니다. 이 상태에서는 해당 화면을 자동 처리하지 못하며 전투 근거가 사라지면 오류 정지합니다.
- 장면·대화 넘기기는 기본 꺼짐이며 실제 넘기기 화면의 OCR 영역 검증 후 사용하세요.
- 오류 후 10분 자동 재개 옵션은 아직 구현하지 않았습니다. 사용자 정지 후 자동 재개하지 않습니다. 수동 ‘현재 화면 재판별 후 시작’은 충돌 없는 인식 단계에서만 시작합니다. 일반 시작을 전투·결과·보상·목적지·입장 상세 화면에서 누르면 메뉴를 열지 않고 재판별 옵션을 켜라는 안내로 정지합니다.
- 광기의 동굴·흩어진 물길은 UI에 표시하지만, 각 목적지의 전투 근거 자료가 없어 실행을 차단합니다.

## Windows 준비

1. OpenCvSharp 실행에 필요한 [Microsoft Visual C++ 2015–2022 x64 재배포 패키지](https://aka.ms/vs/17/release/vc_redist.x64.exe)와 Windows 한국어 OCR 언어 기능을 설치합니다. `Windows.Media.Ocr`의 `ko-KR` 엔진이 없으면 설명을 표시하고 중단합니다.
2. 신뢰할 수 있는 [Interception 공식 프로젝트](https://github.com/oblitum/Interception) 배포본으로 드라이버를 설치하고 필요한 재부팅을 완료합니다. 드라이버 설치는 이 프로그램이 수행하지 않습니다.
3. x64 `interception.dll`을 실행 파일 옆에 둡니다. DLL은 이 저장소/압축본에 포함하지 않습니다. 해당 프로젝트 라이선스와 배포 조건을 확인하세요.
4. 관리자 권한으로 실행합니다. DLL 로드·컨텍스트·키보드·마우스 장치 검사가 성공해야 합니다. F10 등록 실패 시 실행을 차단합니다.
5. 게임 제목은 ‘마비노기 모바일’이어야 하며 창은 하나만 열어주세요. 시작 후 3초 안에 게임을 활성화합니다. 다른 창이 위에 겹치지 않게 하세요. 데스크톱 픽셀 캡처 방식입니다.

## GitHub에서 다운로드

저장소에 소스와 `.github/workflows/windows-build.yml`을 올린 뒤, GitHub의 **Actions → Windows package**에서 실행합니다. `main`에 push하면 자동 실행되며, 수동 실행도 가능합니다. 성공한 실행 화면 하단 **Artifacts → abyss-auto-win-x64**에서 ZIP을 다운로드할 수 있습니다. GitHub 로그인이 필요하며 아티팩트 보관 기간은 14일입니다.

이 작업은 Windows x64 빌드와 35개 결정 규칙 테스트를 실행합니다. 설치된 한국어 OCR로 45초 이내 저장 화면 검사를 시도합니다. 지난 러너의 5분 시간 초과로 인해 CI에서는 언어 팩 설치를 더 이상 시도하지 않습니다. 결과는 실행 요약과 `validation/windows-ci`에 기록하며, OCR 미설치·실행 불가를 통과로 취급하지 않습니다. 게임 입력·실제 반복 검증은 수행하지 않습니다. Interception DLL과 드라이버는 포함하지 않습니다.

## 빌드

.NET 8 SDK가 있는 Windows에서 PowerShell:

```powershell
./build.ps1
```

`artifacts/windows/AbyssAuto.exe`를 실행합니다. 자체 포함 배포이므로 대상 PC에는 별도 .NET 런타임이 필요하지 않습니다. Interception DLL·드라이버·한국어 OCR은 별도입니다.

```powershell
dotnet test tests/AbyssAuto.Tests/AbyssAuto.Tests.csproj -c Release
```

Linux에서도 Windows 대상 교차 빌드와 순수 결정 규칙 테스트는 가능합니다. WinForms, Windows OCR, 화면 캡처, Interception은 Windows에서만 검증할 수 있습니다.

## 이미지 등록과 오프라인 검증 — 먼저 실행

제공된 `Downloads.zip`의 7개 원본과 실제 전투 중 실패 캡처 2개(모두 1297×873)는 배포본의 `validation/screens`에, 추출한 사진 6개는 `images`에 포함되어 있습니다. **다시 사진을 등록할 필요는 없습니다.** 출처와 잘라낸 좌표는 `validation/template-manifest.json`에 기록했습니다.

먼저 Windows에서 압축을 푼 폴더의 `validate-screens.ps1`을 PowerShell로 실행하세요. 관리자 권한과 Interception 없이 **실제 프로그램과 동일한 Windows OCR·OpenCV·색상 경로**로 9개 저장 화면을 검사합니다. 입력은 보내지 않습니다.

```powershell
powershell -File .\validate-screens.ps1
```

결과는 `validation/windows-results/windows-ocr-report.json`과 영역 표시 사진입니다. 총 108개 판정(12개 대상 × 9개 화면)을 기대값과 비교합니다. 종료 코드 0=전체 일치, 1=불일치, 2=실행/의존성 오류입니다. 오류 시 `windows-ocr-error.txt`를 확인하세요. 이 검사는 제공된 저장 화면만 다루므로 버튼 없는 별도 화면·로딩·부활·재접속·실제 입력은 추가 검증해야 합니다. `skip`·`purchase`는 부정 사례만 포함합니다. 출력 폴더는 매 실행마다 갱신하므로 보관할 결과는 따로 복사하세요.

새로 촬영한 화면으로 교체할 때는 **리사이즈하지 않은 원본 PNG 파일**을 사용합니다. 실행 프로그램에서 ‘화면·템플릿 등록’을 누르고 전체 화면을 고른 뒤 역할을 선택합니다. 설정 영역을 잘라 미리 보여주므로 아이콘·글자·버튼 모양이 실제로 포함되는지 확인한 후 저장하세요. 이름만으로 내용이 확인되었다고 처리하지 않습니다.

허상의 정박지 기본 사진:

| 전체 화면 | 선택할 역할 | 저장 파일 |
|---|---|---|
| 메뉴 열림 | 메뉴의 어비스 아이콘·글자 | images/a_abyss.png |
| 목적지 목록 | 허상의 정박지 배너 | images/a_husang.png |
| 입장 상세 | 입장하기 버튼 | images/a_enter.png |
| 결과 터치 | 결과 화면 터치 안내 | images/touch.png |

광기의 동굴·흩어진 물길 배너 사진도 추출해 포함했으나, 해당 목적지의 전투 근거가 없어 실행은 차단합니다. 다시 하기는 OCR+색상으로 판정하며 별도 사진을 요구하지 않습니다. `touch2.png` 등 추가 사진도 설정의 Images 배열에 등록할 수 있습니다.

‘저장 화면 인식 검사’에서 메인·메뉴·목록·입장·전투·결과·보상 원본 PNG를 선택하세요. 입력 없이 각 영역의 실제 OCR, 최고 사진 점수, 배점, 색상, 판정 사유를 기록합니다. `captures/offline`의 영역 표시 이미지와 JSON을 확인합니다. 비슷한 글자, 로딩, 버튼 없는 화면도 검사해 잘못 합격하지 않는지 확인하고 `targets.json`의 영역·Threshold를 대상별로 조정하세요. .75는 검증된 정확도 수치가 아닙니다.

설정은 **실행 파일 옆**의 `scenario.json`, `targets.json`, `images`만 읽으며 시작할 때 다시 읽습니다. 개발 폴더 설정은 빌드 시 배포 폴더로 복사됩니다. 실행 폴더에서 조정한 자료를 재빌드 전에 백업하세요. 중요 설정을 수정한 경우 시작 전에 오프라인 검사를 다시 수행하세요.

영역은 `[Left,Top,Right,Bottom]`, 제목 표시줄 포함 창 기준 픽셀입니다. 전체 모니터 절대좌표가 아닙니다. 창 크기·UI 배율·제목 표시줄 기준을 바꾸면 자동 확대하지 말고 다시 영역을 맞추세요.

## 실게임 단계 검증 — 아직 미수행

1. 목표 횟수 **1**로 첫 실행. 메인에서 ESC 한 번, 어비스, 허상의 정박지, 입장 감지 후 1초 뒤 SPACE, 던전 목표 이름과 ‘부활 6회’ 하위 목표로 전환 확인을 관찰합니다.
2. 전투 중 프로그램이 결과용 입력을 보내지 않는지 확인합니다. 결과 문구 클릭 후 보상 화면을 확인하면 1판 완료로 기록하고 정지합니다.
3. 보상 화면에서 목표 횟수 1 + ‘현재 화면 재판별 후 시작’을 선택합니다. 다시 하기를 눌러 버튼이 사라지고 던전 목표가 두 번 확인되는지 검증합니다. 이 작업은 다음 판 결과까지 진행하므로 두 번째 진입 확인 후 F10으로 정지해도 됩니다.
4. F10을 카운트다운·대기·재시도 중 각각 눌러 중단을 확인합니다. 다른 창 활성화·마우스 개입·다시 하기 없는 화면·로딩·행동불능 화면에서 잘못된 입력이 없어야 합니다.
5. 위 과정과 정상/부정 화면의 판정이 확인된 뒤에만 횟수를 늘립니다. 장시간 반복 검증은 아직 하지 않았습니다.

오류 사진과 마지막 입력·시각·단계·OCR·사진 점수·색상 근거는 `captures`에 저장합니다. 최근 40쌍을 유지합니다. 로그는 약 2MB씩 최대 4개입니다. UI 로그는 약 60,000자를 넘으면 줄입니다. 오프라인 검증 결과는 별도 폴더이며 수동 관리합니다.

## 구성

- `Engine.cs`: 취소 가능한 순차 실행, 전환 검증, 재시도, 수동 재분류
- `Vision.cs`: 한국어 OCR, 사진·색상 판정. 입력 없음
- `Desktop.cs`: 창/캡처 및 Interception 입력. 키·버튼은 예외·취소에도 해제
- `DecisionRules.cs`: 플랫폼 독립 문구/전환 결정 및 회귀 테스트 대상
- `Configuration.cs`, `scenario.json`, `targets.json`, `images/`: 실행 위치 기준 구성
- `MainForm.cs`, `Journal.cs`: 조작 화면, 오프라인 검사/등록, 제한 로그
- `OfflineValidator.cs`, `validate-screens.ps1`: Windows에서 입력 없이 동일 인식 경로 검증
- `tools/validate_templates.py`: Python OpenCV 4.10.0의 사진 채널 비교 검사
